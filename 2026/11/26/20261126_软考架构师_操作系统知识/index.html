学习日期：2026-11-26
专题：操作系统知识
说明：本节在软考架构设计师中稳定占 3～5 分。新版教材删减了部分内容，但考试仍会涉及旧版知识点，因此以教材为主、补充为辅。

今天没有继续 Flink，转向软考高级架构师的备考。第一块是操作系统——内容多、概念密，但考点相对固定，适合用结构化笔记来记。

一、操作系统概述

1. 定义与作用

操作系统是计算机系统的资源管理者，包含对软硬件资源实施管理的一组程序。它通过 CPU 管理、存储管理、设备管理和文件管理，对资源合理分配，改善共享与利用程度。

操作系统通常由**内核（Kernel）**和大量配套软件组成：

  • 内核提供进程管理、存储管理、文件管理和设备管理等功能，是操作系统中最基本的部分
  • 配套软件包括图形界面、常用应用程序、实用程序（任务管理器、磁盘清理、杀毒软件）以及应用框架、编译器、程序库等

三个核心作用：

  1. 管理计算机中运行的程序，分配各种软硬件资源
  2. 为用户提供友善的人机界面
  3. 为应用程序的开发和运行提供高效率的平台

此外还有辅助用户操作、处理软硬件错误、监控系统性能、保护系统安全等作用。

2. 四个核心概念

概念 含义
并发 一段时间内宏观上有多个程序同时运行，但单 CPU 环境下每个时刻只有一个程序在执行
共享 系统中的资源（硬件和信息资源）可被多个并发执行的进程共同使用，而非被一个进程独占
虚拟 把物理上的一个实体变成逻辑上的多个对应物，或把物理上的多个实体变成逻辑上的一个对应物
异步 多道程序环境下允许多个进程并发执行，但资源有限，进程执行”走走停停”，而非一贯到底

3. 五大功能

  1. 进程管理——对处理机的执行”时间”进行管理，包括进程控制、同步、通信和调度
  2. 文件管理——文件存储空间管理、目录管理、读/写管理和存取控制
  3. 存储管理——对主存”空间”进行管理，包括分配与回收、存储保护、地址映射和主存扩充
  4. 设备管理——对硬件设备的管理，包括 I/O 设备的分配、启动、完成和回收
  5. 作业管理——任务、界面管理、人机交互、图形界面、语音控制和虚拟现实

4. 操作系统分类

类型 要点
批处理 单道批处理与多道批处理，主机与外设可并行
分时 CPU 工作时间划分为很短的时间片，轮流为各终端用户服务
实时 对外来信息足够快地处理，在被控对象允许的时间范围内做出反应；对交互能力要求不高，但可靠性要求高
网络 联网计算机共享资源，提供电子邮件、文件传输、共享硬盘和打印机等服务。三种模式：集中模式、客户端/服务器模式、对等模式
分布式 多台分散计算机连接而成，无主次之分，任意两台可通过通信交换信息；是网络操作系统的更高级形式
微型计算机 Windows、macOS、Linux
嵌入式 运行在嵌入式智能芯片环境中，统一协调、处理、指挥和控制芯片及所控制的部件装置

嵌入式操作系统的五个特点：

  1. 微型化——占用资源和系统代码量少（内存少、字长短、运行速度有限、能源少）
  2. 可定制——能运行在不同微处理器平台上，针对硬件变化配置结构与功能
  3. 实时性——常用于过程控制、数据采集、传输通信等多媒体信息及关键领域，对实时性要求高
  4. 可靠性——构件、模块和体系结构须达到应有可靠性，关键应用还要提供容错和防故障措施
  5. 易移植性——通常采用硬件抽象层（HAL）和板级支撑包（BSP）的底层设计技术

二、进程管理

1. 进程的组成与状态

进程由三部分组成：

  • 进程控制块（PCB）——唯一标志
  • 程序——描述进程要做什么
  • 数据——存放进程执行时所需数据

基础状态是三态图，需要熟练掌握三种状态之间的转换关系。

注意阻塞态不能直接回到运行态，必须先进就绪队列等待调度——这是选择题里常设的陷阱。

2. 进程资源图

进程资源图用来表示进程和资源之间的分配与请求关系：

  • P 代表进程，R 代表资源，R 方框中的圆球数表示该类资源的数量
  • R1 指向 P1：表示 R1 有一个资源已分配给 P1
  • P1 指向 R2：表示 P1 还需要请求一个 R2 资源才能执行

阻塞节点：进程所请求的资源已全部分配完毕，无法获取所需资源，被阻塞无法继续。
非阻塞节点：进程所请求的资源还有剩余，可以分配给该进程继续运行。

当进程资源图中所有进程都是阻塞节点时，即陷入死锁状态。

化简方法：先看系统剩余多少未分配资源，找出非阻塞进程，去掉它的所有边形成孤立点，回收分配给它的资源；然后继续找下一个非阻塞进程，逐个变成孤立点。最终所有资源和进程都变成孤立点，图即化简完成。

3. 进程同步与互斥

概念 含义
临界资源 各进程间需要以互斥方式访问的资源
临界区 进程中对临界资源实施操作的那段程序，本质是一段代码
互斥 某资源同一时间只能由一个任务单独使用，使用时加锁，用完解锁（如打印机）
同步 多个任务可以并发执行，但有速度差异，一定情况下停下等待（如自行车和汽车）

信号量：

  • 互斥信号量——对临界资源采用互斥访问，使用后其他进程无法访问，初值为 1
  • 同步信号量——对共享资源的访问控制，初值一般是共享资源的数量

P 操作（申请资源）：S = S - 1

  • 若 S >= 0，执行 P 操作的进程继续执行
  • 若 S < 0，置该进程为阻塞状态（无可用资源），插入阻塞队列

V 操作（释放资源）：S = S + 1

  • 若 S > 0，执行 V 操作的进程继续执行
  • 若 S <= 0，从阻塞状态唤醒一个进程，插入就绪队列，然后执行 V 操作的进程继续

S < 0 时 |S| 就是等待队列里的进程数——这个结论常直接用来出计算题。

4. 经典问题：生产者与消费者

三个信号量：

  • S0：互斥信号量，仓库独立使用权
  • S1：同步信号量，仓库空闲个数
  • S2：同步信号量，仓库商品个数

5. 前趋图

前趋图用来表示哪些任务可以并行执行、哪些任务之间有顺序关系。例如 A、B、C 可以并行执行，但必须三者都完成后才能执行 D——既确定了任务间的并行，也确定了先后顺序。用 PV 操作控制前趋图的进程同步是高频考点。

6. 进程调度

调度方式：

  • 可剥夺：更高优先级进程到来时，强行将正在运行进程的 CPU 分配给它
  • 不可剥夺：高优先级进程必须等待当前进程自动释放 CPU

三级调度：

级别 别名 作用
高级调度 长调度 / 作业调度 / 接纳调度 决定输入池中哪个后备作业调入主系统，成为就绪进程。一个作业只需经过一次
中级调度 中程调度 / 对换调度 决定交换区中哪个就绪进程调入内存，直接参与 CPU 竞争
低级调度 短程调度 / 进程调度 决定内存中哪个就绪进程占用 CPU。最活跃、最重要，对系统影响很大

调度算法：

算法 要点
先来先服务 FCFS 先到达的进程优先分配 CPU，用于宏观调度
时间片轮转 RR 分配给每个进程相同大小的 CPU 时间片，轮流使用，很公平，用于微观调度
优先级调度 每个进程拥有优先级，优先级大的先分配 CPU
多级反馈调度 时间片轮转与优先级结合。设置多个就绪队列 1、2、3…n，各队列优先级和时间片长度不同；新进程先进入队列 1 末尾，按 FCFS 执行时间片，未完成则转入队列 2 末尾，如此重复

7. 死锁

定义：多个进程因竞争资源而造成的一种僵局，若无外力作用，这些进程都无法继续推进。

四个必要条件：

  1. 资源互斥
  2. 每个进程占有资源并等待其他资源
  3. 系统不能剥夺进程资源
  4. 进程资源图是一个环路

处理策略：

策略 说明
死锁预防 采用策略限制并发进程对资源的请求，破坏四个条件之一，使系统任何时刻都不满足死锁条件
死锁避免 用银行家算法提前计算一条不会死锁的资源分配路径，否则不分配资源。相当于借贷：考虑对方还得起才借
死锁检测 允许死锁产生，系统定时运行检测程序，检测到后设法解除
死锁解除 强制剥夺资源、撤销进程等

死锁资源计算（高频计算题）：

系统内有 n 个进程，每个进程都需要 R 个资源：

  • 发生死锁的最大资源数：n × (R - 1)
  • 不发生死锁的最小资源数：n × (R - 1) + 1

8. 线程

传统进程有两个属性：可拥有资源的独立单位、可独立调度和分配的基本单位。

引入线程的原因：进程在创建、撤销和切换中，系统需付出较大的时空开销，因此系统中进程数目不宜过多、切换频率不宜太高，限制了并发程度。引入线程后把两个属性分开——线程作为调度和分配的基本单位，进程作为独立分配资源的单位。

线程是进程中的一个实体，基本上不拥有资源，只拥有运行中必不可少的资源（程序计数器、一组寄存器和栈）。它可与同属一个进程的其他线程共享进程拥有的全部资源（公共数据、全局变量、代码、文件），但不能共享线程独有的资源（如栈指针等标识数据）。

9. 中断

概念 含义
中断 由于某些事件出现，中止现行进程运行，由操作系统处理该事件，待适当时候让被中止进程继续运行
中断源 引起中断的事件
中断处理程序 对出现的事件进行处理的程序
中断响应 由硬件的中断装置暂停现行进程，让操作系统的中断处理程序占用处理器

中断分类：

  1. 程序性中断——程序执行中发现程序性质错误或出现特定状态，如浮点溢出、用户态使用特权指令、内存越界、跟踪
  2. 外中断——外部非通道式装置引起的中断，如时钟中断、操作员控制台中断、多处理机系统中 CPU 间通信中断
  3. 输入输出中断——外部设备或通道操作正常结束或发生错误，如打印完成、缺纸、驱动器中没有磁盘
  4. 硬件故障中断——机器发生故障，如电源故障、内存单元奇偶校验错
  5. 访管中断——对操作系统提出请求，如创建进程、I/O 传输、打开文件、关闭文件、文件读写等系统调用

三、存储管理

1. 分区存储管理

方式 说明 碎片
固定分区 静态分区，将主存分为若干固定分区，作业装配进去 分区大小与作业需求不同，产生内部碎片
可变分区 动态分区，作业转入时按需要大小划分 不存在内部碎片，但整片主存被切割成许多块，产生外部碎片
可重定位分区 移动所有已分配区域使其成为连续区域，把外部细小碎片合并成大分区 只在外部作业请求空间得不到满足时进行

2. 分页存储管理

逻辑页分为页号和页内地址，页内地址就是物理偏移地址。页号与物理块号并非按序对应，需要查询页表，找到页号对应的物理块号，再用物理块号加上页内地址才是真正运行时的物理地址。

  • 优点：利用率高、碎片小、分配及管理简单
  • 缺点：增加系统开销，可能产生抖动现象

地址转换计算：页面大小 4KB（即 2^12），逻辑地址 1D16H 的低 3 位十六进制 D16H 是页内偏移，高位 1 是页号。查页表得页号 1 对应物理块号 3，因此物理地址为 3D16H。

3. 页面置换算法

算法 要点
OPT 最优算法，理论上无法实现，在进程执行完后计算最佳效率，用来衡量其他算法
FIFO 先调入内存的页先被置换淘汰，会产生抖动现象——分配的页数越多，缺页率可能反而越高
LRU 最近最少使用，根据局部性原理效率高，不产生抖动。使用大量计数器，但比 LFU 少
LFU 最不经常使用，淘汰访问次数最少的页面

淘汰原则：优先淘汰最近未访问的，而后淘汰最近未被修改的页面。

快表：一块小容量的相联存储器，由快速存储器组成，按内容访问、速度快，可从硬件上保证按内容并行查找，一般存放当前访问最频繁的少数活动页面的页号。

  • 快表 = 页表存于 Cache 中
  • 慢表 = 页表存于内存上
  • 慢表需访问两次内存才能取出页，快表只需访问一次 Cache 和一次内存，因此更快

4. 分段存储管理

将进程空间分为一个个段，每段有段号和段内地址。与页式存储不同，每段物理大小不同，分段是根据逻辑整体划分的。

段表与页表内容也不同：页表直接是逻辑页号对应物理块号；段表有段长和基址两个属性，才能确定一个逻辑段在物理段中的位置。

段式地址越界判断：逻辑地址 (段号, 段内偏移) 中的偏移必须小于该段的段长，否则无法转换。

5. 段页式存储管理

对进程空间先分段、后分页。

  • 优点：空间浪费小、存储共享容易、存储保护容易、能动态链接
  • 缺点：管理软件增加，复杂性和开销随之增加，需要的硬件和占用内容也有所增加，执行速度大大下降

四、设备管理

1. 概述

设备是计算机系统与外界交互的工具，负责计算机与外部的输入/输出工作，常称为外部设备（外设）。负责管理设备和输入/输出的机构称为 I/O 系统。

I/O 系统由设备、控制器、通道（具有通道的计算机系统）、总线和 I/O 软件组成。

设备分类：

  • 按数据组织：块设备、字符设备
  • 按功能：输入设备、输出设备、存储设备、网络联网设备、供电设备
  • 按资源分配：独占设备、共享设备、虚拟设备
  • 按数据传输速率：低速设备、中速设备、高速设备

设备管理的主要功能：动态掌握并记录设备状态、设备分配和释放、缓冲区管理、实现物理 I/O 设备的操作、提供设备使用的用户接口及设备的访问和控制。

2. I/O 软件层次

以用户程序读硬盘文件为例：

  1. 与设备无关软件检查高速缓存中有无要读的数据块，没有则调用设备驱动程序
  2. 设备驱动程序向 I/O 硬件发出请求
  3. 用户进程阻塞，等待磁盘操作完成
  4. 磁盘操作完成，硬件产生中断，转入中断处理程序
  5. 中断处理程序检查原因，唤醒用户进程取回数据，结束此次 I/O 请求

3. SPOOLING 技术

一台独占设备同一时间只能由一个进程使用，其他进程只能等待，且不知道什么时候空闲，极大浪费外设工作效率。

SPOOLING（外围设备联机操作）：在外设上建立两个数据缓冲区——输入井和输出井。无论多少进程都可以共用这一台打印机，只需将打印命令发出，数据排队存储在缓冲区中，打印机自动按顺序打印。实现了物理外设的共享，让每个进程都感觉在使用一台打印机，即物理设备的虚拟化。

4. I/O 系统的五种工作方式

方式 要点
程序控制方式 CPU 执行一段 I/O 程序实现主机与外设间数据传送。分无条件传送（端口总是就绪，CPU 无须查询）和程序查询方式（CPU 循环查询外设状态，未就绪则等待）
程序中断方式 引入中断以提高 I/O 能力和 CPU 效率。分五个阶段：中断请求、中断判优、中断响应、中断处理、中断返回。CPU 无须等待也不必查询状态
DMA 方式 在主存与外设间实现高速、批量数据交换，使用 DMA 控制器（DMAC）控制和管理数据传输。DMAC 与 CPU 共享系统总线，具有独立访问存储器的能力
通道方式 高级 I/O 控制部件，在硬件基础上利用软件手段实现对 I/O 的控制和传送，更多地免去 CPU 介入，提高主机与外设的并行程度
I/O 处理机 也称外围处理机，具有丰富的指令系统和完善的中断系统，专用于大型高效计算机系统处理外围设备的 I/O

通道按传送方式分三类：

  • 字节多路通道——简单的共享通道，连接与管理多台低速设备
  • 选择通道——又称高速通道，可物理连接多个设备，但一段时间内只能选择一台设备传送数据，该设备独占整个通道
  • 数组多路通道——结合字节多路通道和选择通道的特点，有多个子通道，既像字节多路通道那样分时共享总通道，又能像选择通道那样成组传送数据

五、文件管理

1. 索引文件结构

索引节点分为直接索引和间接索引：

  • 直接索引：索引节点直接存放数据块内容
  • 一级间接索引：直接盘存放一级地址，一级地址再指向数据块
  • 二级间接索引：直接盘存一级地址，一级地址指向二级地址表，二级地址再指向数据块

以物理盘块 4KB 为例：

  • 一个地址项 4 字节，每个索引块可存 4096 / 4 = 1024 个地址
  • 一级间接可表示 1024 × 4KB = 4096KB 数据
  • 二级间接可表示 1024 × 1024 × 4KB 数据

2. 文件的存取方法

  • 顺序存取——对文件中的信息按顺序依次读/写
  • 随机存取——可以按任意次序随机读/写

3. 文件存储空间管理

方法 说明
空闲区表 将外存上连续的未分配区域称为”空闲区”，为所有空闲区建立一张表，每个表项对应一个空闲区。适用于连续文件结构
位示图 在外存上建立一张 Bitmap，每一位对应一个物理块，0 和 1 分别表示空闲和占用
空闲块链 每个空闲物理块中有指向下一个空闲块的指针，所有空闲块构成链表，头指针放在特定位置（如管理块中）。不需要磁盘分配表，节省空间
成组链接法 将空闲块分成若干组，每 100 个为一组，每组第一个空闲块登记下一组的物理盘块号和空闲块总数。若某组第一个空闲块号为 0，表示这是最后一组

位示图大小计算：每页 4KB，总容量 16GB，则物理块数为 16GB / 4KB = 4M 块，每块用 1 bit 表示，位示图大小为 4M bit = 512KB。

六、典型真题

1. 进程状态转换

进程从运行状态变成就绪状态的条件是（　）。
A. 主动让出 CPU　B. 信号量执行 wait() 方法　C. 缺页中断　D. 请求磁盘

答案：A。主动让出 CPU（如时间片用完）使进程从运行态回到就绪态；请求磁盘或 wait() 会进入阻塞态。

2. 死锁预防

以下（　）不属于操作系统死锁预防的办法。
A. 破坏请求和保持　B. 破坏互斥　C. 破坏不可抢占　D. 破坏循环等待

答案：B。死锁的四个必要条件中，资源互斥本身无法破坏，预防措施针对其余三个条件。

3. 非抢占式调度时间计算

单 CPU 系统中有两个任务 P1、P2。P1 依次执行 40ms 计算、60ms I/O、40ms 计算；P2 依次执行 100ms 计算、40ms I/O、40ms 计算。P2 晚启动 20ms，采用非抢占式调度，执行完两个任务的总时间是（　）ms。
A. 200　B. 220　C. 240　D. 260

答案：B（220ms）。

4. 段式地址越界

某进程段表如下，逻辑地址（　）可以转换。
A. (0, 1597)、(1, 30)、(3, 1390)
B. (0, 128)、(1, 30)、(3, 1390)
C. (0, 1597)、(2, 98)、(3, 1390)
D. (0, 128)、(2, 98)、(4, 1066)

答案：B。0 段段长只有 600，1597 越界；4 段段长只有 960，1066 越界。含这两者的选项都排除。

5. 索引节点与文件大小

文件索引节点有 8 个地址项，每项 4 字节，其中 5 个直接地址索引、2 个一级间接、1 个二级间接，磁盘索引块和数据块大小均为 1KB。访问逻辑块号 5 和 518 分别采用（27），单个文件最大长度是（28）KB。
（27）A. 直接和一级　B. 直接和二级　C. 一级和二级　D. 一级和一级
（28）A. 517　B. 1029　C. 16513　D. 66053

答案：C、D。

  • 直接地址覆盖 0～4；5 落在第一个一级间接范围（5～260），518 落在二级间接范围（518 > 5 + 2×256 = 517）
  • 最大块数 = 5 + 2×256 + 256×256 = 66053 块，每块 1KB，即 66053KB
